7. ARQUITETURA E ESCALABILIDADE

Auth valida chaves; flag mantém definições; targeting mantém regras de
segmentação; evaluation decide a flag, usa Redis como cache e publica eventos
em SQS; analytics consome eventos e persiste no DynamoDB com escrita
condicional por event_id.

PostgreSQL/RDS é persistência relacional dos dados operacionais.
Redis/ElastiCache é cache temporário de avaliação. DynamoDB é persistência
NoSQL dos eventos de analytics. São responsabilidades distintas.

O HPA por CPU para evaluation e analytics foi usado como workaround compatível
com as restrições de IAM do AWS Academy; o requisito mínimo do PDF pede HPA
por CPU para os dois serviços nessa opção. O PDF descreve KEDA como opção
recomendada/opcional em conta pessoal para escalar analytics pela fila SQS.
CPU é uma métrica suportada pelo HPA/metrics-server; para analytics, processar
a fila aumenta CPU e permite escala, mas não mede diretamente a profundidade
da fila. Escalar Pods não cria nós nem escala RDS.
